# Участие в разработке

Прочитайте корневой AGENTS.md и [архитектуру](architecture.md). Нужны Node.js 24+,
npm и Docker Compose. Установка независима:

```sh
npm --prefix server install
npm --prefix web install
```

Не вводите npm/pnpm workspace, общий runtime-пакет, ORM или query builder.
Все SQL пишем вручную; значения передаём параметрами, имена экранируем отдельно.
Не добавляйте тесты до отдельного запроса.

## Frontend

Сохраняйте FSD и публичные index.ts. App связывает страницы; features используют entities/shared;
shared не зависит от верхних слоёв. RTK Query — единственный слой серверного состояния.
Компоненты используют семантические Tailwind токены: canvas/surface/elevated/line/ink/secondary/
muted/accent/primary/success/danger. Не прописывайте отдельные светлые цвета в компонентах.
Проверяйте светлую/тёмную тему, диалоги, длинные имена, пустые состояния и узкий экран.

## Backend

Контроллеры принимают DTO; сервис организует операции; SQL-репозиторий хранит каталог;
адаптеры знают внешний движок. Новые API-типы обновляйте в обеих локальных копиях контрактов.
Ошибка внешнего драйвера не должна попадать в ответ, историю или лог с реквизитами.

Для нового движка реализуйте Connector.test/introspect/rows, зарегистрируйте адаптер,
обновите DTO/контракты/форму и SQL CHECK отдельной миграцией. Не храните rows в каталоге.
Проектируйте интроспекцию с ограничением количества объектов и времени работы.

## SQL-миграции

Добавляйте новый пронумерованный .sql в server/src/database/migrations, не переписывайте
уже применённый файл. Runner использует транзакцию и advisory lock; версии — schema_migrations.
Nest копирует SQL в dist. Существующие snapshots и profiles должны сохраняться при обновлении.
При изменении модели обновите docs/data-model.md и docs/api.md.

## Проверки

В каждой папке отдельно:

```sh
npm run format
npm run build
npm run lint
npm run format:check
```

Для connector-изменений вручную проверьте каждый движок: test/create/sync, метаданные PK/FK/
индексов, чтение двух страниц, невалидный пароль и чужой objectId. Не удаляйте пользовательские
профили или данные ради smoke-проверки. Временные элементы создавайте с явным именем.

Скрипты учебных баз запускаются в контейнерах через штатные psql/mysql/mongosh/mongoimport.
Оригиналы дампов и лицензии лежат в server/docker/samples; source/checksums — manifest.json.
Изменяйте bootstrap отдельно от vendor SQL. В PR описывайте конечное поведение и выполненные
проверки, обновляйте соответствующий документ, не добавляйте секреты в git.
