# SQL-редактор

Экран `/sql` работает с сохранёнными подключениями PostgreSQL и MySQL. Подключение можно
выбрать в верхней части экрана либо открыть кнопкой **SQL** со страницы базы. Monaco Editor
собран вместе с web-приложением и не загружает код с CDN.

## Выполнение

- **Выполнить** отправляет весь текст редактора.
- ⌘+Enter на macOS или Ctrl+Enter на Windows/Linux отправляет выделенный фрагмент; если
  выделения нет — весь текст.
- Лимит интерфейса: 100, 500 или 1000 строк на result set.
- PostgreSQL допускает несколько выражений и показывает отдельную вкладку для каждого
  набора результата. MySQL допускает одно выражение на запрос.
- Для DML/DDL без колонок показываются команда и число затронутых строк.
- Повторяющиеся имена колонок не теряются, поскольку API передаёт строку массивом значений.

Сервер ограничивает SQL 100 000 символами, выполняет его в короткой нативной сессии и
закрывает соединение после ответа. Connection timeout — 5 секунд, query timeout — около
30 секунд. Длинные строки, binary и вложенные значения преобразуются в ограниченный
JSON-safe вид перед отправкой.
Ошибки возвращаются безопасной парой `code`/`message`: stack, DSN, внутренний адрес и сырой
текст драйвера в REST-ответ не попадают.

## Права и данные

Редактор не пытается классифицировать SQL. SELECT, DML и DDL разрешает или отклоняет сама
подключённая БД по grants сохранённого пользователя. Поэтому для исследовательских профилей
рекомендуется отдельный read-only пользователь; тестовые учётные записи `enjoyer` именно
такие. После успешного DDL нужно вручную нажать **Обновить структуру**, потому что активная
версия каталога не меняется автоматически.

Текст и результаты запросов не сохраняются в служебном PostgreSQL, логах синхронизации или
REST-истории. Последний черновик каждого подключения хранится только в localStorage текущего
браузера. Пароль на экран SQL не передаётся. Отмена выполняющегося запроса, streaming больших
result sets, история и MongoDB playground пока не реализованы.
