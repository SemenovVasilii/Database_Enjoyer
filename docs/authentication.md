# Авторизация по email

DatabaseEnjoyer использует passwordless-вход по одноразовому коду. Сценарий повторяет
`sobeslife_mono/dev`: пользователь вводит email, получает шестизначный код и после проверки
получает пару access/refresh JWT. Отдельной регистрации нет — первая успешная проверка кода
создаёт пользователя автоматически.

## Поток входа

1. `POST /api/auth/otp/send` нормализует email, генерирует криптографически случайный код и
   отправляет письмо через Resend. В локальной среде без Resend код выводится в лог server.
2. В служебном PostgreSQL сохраняется SHA-256 digest с отдельным `AUTH_OTP_PEPPER`, а не код.
   Новый код заменяет предыдущий и действует 10 минут.
3. `POST /api/auth/otp/verify` допускает не более пяти неверных попыток. Код одноразовый:
   успешная проверка удаляет его.
4. Сервер находит пользователя по нормализованному email или создаёт его, затем возвращает
   `accessToken` и `refreshToken`.
5. Web хранит пару в localStorage. RTK Query добавляет `Authorization: Bearer <accessToken>`
   к REST-запросам и очищает сессию при 401.

Access JWT живёт 12 часов, refresh JWT — 168 часов по умолчанию. Они подписываются разными
секретами, имеют `aud=web`, `iss=database-enjoyer` и claim `type`. Маршрут
`POST /api/auth/refresh` выдаёт новую пару. Кнопка выхода очищает локальные токены; серверная
сессия не хранится, поэтому принудительный отзыв отдельного JWT пока не поддерживается.

## Изоляция данных

`connections.owner_id` и `databases.owner_id` ссылаются на `users.id`. Каждый запрос списка,
структуры, строк, синхронизации, SQL и удаления фильтруется одновременно по UUID ресурса и
UUID текущего пользователя. Для чужого UUID API возвращает 404 и не раскрывает его наличие.
Пароли внешних БД по-прежнему находятся отдельно в `connection_secrets` и шифруются.

До миграции `004-email-auth.sql` элементы каталога не имели владельца. Пользователь с email
из `AUTH_BOOTSTRAP_EMAIL` один раз забирает все такие записи после успешного входа. Укажите
в production email фактического владельца до первого запуска новой версии.

## Настройка почты

В production обязательны:

- `RESEND_API_KEY` — API key Resend;
- `RESEND_FROM_EMAIL` — отправитель на подтверждённом домене, например
  `DatabaseEnjoyer <login@example.com>`;
- `AUTH_BOOTSTRAP_EMAIL` — email первого владельца прежних записей;
- три независимых секрета длиной минимум 32 символа: `AUTH_ACCESS_TOKEN_KEY`,
  `AUTH_REFRESH_TOKEN_KEY`, `AUTH_OTP_PEPPER`.

Локально оставьте обе переменные Resend пустыми и найдите код так:

```sh
docker compose logs --tail=100 server
```

Повторную отправку можно запросить через минуту. Не добавляйте реальные ключи и токены в git.
